stage 1: host read-only tool family (11 tools)

Restores the host half under the new shape and adds the tools the README
promised but v0.1.0 never had. Four families, each independently readable and
independently failing:

  tools/roll.mjs      dnd_roll dnd_check dnd_attack dnd_save
                      + dnd_mastery (2024 weapon mastery, all 8 properties)
                      + dnd_dc      (DC ladder + passive scores)
  tools/lookup.mjs    dnd_srd_lookup
  tools/campaign.mjs  dnd_campaign_state dnd_campaign_search + dnd_arc_status
  tools/sheet.mjs     dnd_character_get

Three genuine bugs fixed along the way, each found by a test rather than by
reading:

1. The UTF-8 BOM. The active-campaign marker is written by Python and carries
   a BOM on Windows; JSON.parse then throws on the leading \uFEFF and the tool
   reported "no active campaign" for a marker that plainly existed. v0.1.0 had
   the same bare JSON.parse and the same latent failure. Added stripBom /
   parseJsonLoose in tools/shared.mjs.

2. Spell slots. Two separate defects here. v0.1.0's regex matched the FIRST
   slot row only, so a multi-circle caster silently parsed as single-circle.
   Then the rewrite keyed on a `| Slot |` header — and the real
   morgansfort/alice.md says `| Level |`, so it parsed to zero slots. The
   synthetic fixture had matched the code instead of the data. Both headers
   are now accepted, and the test suite parses the real sheet from disk.

3. Ability cells. Real sheets write `17 (+3)`, not `17`. The raw cell was
   passed through as the ability value, forcing every consumer to re-parse.
   Now returns { score, modifier, raw }.

Also normalized parseInt('pending') -> null instead of NaN.

Performance: dnd_srd_lookup cached nothing and re-parsed a 1453-entry JSON
document on every call; dnd_campaign_search re-read the whole corpus per query.
Both now use an mtime-invalidated cache (MtimeCache), so a dataset rebuild
still invalidates correctly and nothing pays the parse twice. A no-fs mount
degrades with a message instead of failing.

Testing: 45 assertions across three suites, all wired into `npm test`.
  - test/sheet-parse.test.mjs  17 cases incl. the real campaign sheet
  - test/host.test.mjs         22 cases mounting the coordinator against a
                               mock fs and exercising every tool for real
  - test/build.test.mjs        the artifact contract from stage 0
`npm run check` runs build + test + verify as one gate.
