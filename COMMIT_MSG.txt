refactor: gate the mount on tools only, keep fs a per-tool requirement

Reverses the inject change from a8bc7df. That commit fixed the live failure by
two means at once — declaring `inject: ['tools','fs']` AND making the families
read the service lazily. Only the second was actually necessary, and the first
was over-broad:

  tools/roll.mjs is six tools of pure arithmetic needing no filesystem.
  Gating the whole plugin on `fs` means a filesystem outage unmounts those six
  as collateral damage, contradicting the per-family isolation the coordinator
  is built around.

The real defect was always the mount-time capture — `const fs = ctx.get('fs')`
reads once, so an apply() that loses the startup race caches undefined forever.
Lazy per-call reads fix that on their own, and additionally survive a
filesystem re-registered later. `fs` is therefore not injected; the five
fs-backed tools each report "fs service unavailable" when it is absent, and the
six pure ones keep working.

Dependency shape is now, deliberately:
  tools  hard   — without it the plugin is meaningless
  fs     soft, but required by 5 of the 11 tools
  logger soft   — warnings only

The regression test was strengthened accordingly: it now asserts all 11 tools
register with NO fs present, that a pure tool still rolls, and that the
fs-backed tool picks the service up the moment it appears.
